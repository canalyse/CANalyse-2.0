# CANalyse User Manual

## Overview

CANalyse is a comprehensive CAN bus analysis and testing tool designed for automotive security research. It provides capabilities for sniffing, analyzing, fuzzing, and replaying CAN bus traffic to identify and test vehicle control systems.

## Prerequisites

- **Hardware**: CAN bus interface (USBtin, CANalyst-II, PCAN, etc.) connected to the target vehicle's CAN network
- **Software**: Python 3.8+ with required dependencies
- **Permissions**: Appropriate access to CAN interfaces on your system

## Installation

### Option 1: Install from PyPI (Recommended)
```bash
pip install canalyse
```

### Option 2: Install from Source
```bash
git clone https://github.com/canalyse/CANalyse-2.0.git
cd CANalyse-2.0
pip install -e .
```

## Quick Start

1. **Launch the application**:
   ```bash
   canalyse
   ```

2. **Configure settings**:
   - Set your CAN interface (e.g., `can0`, `vcan0`)
   - Choose bus type (e.g., `socketcan`, `pcan`)
   - Configure Telegram bot token if using remote access

3. **Basic workflow**:
   - Scan CAN traffic
   - Analyze captured data
   - Test with fuzzing
   - Replay identified messages

## Core Features

### 1. CAN Bus Scanning
Capture and log CAN bus traffic for analysis.

**Usage**:
```
scan("can0", "30")
```
- Parameters: `channel` (string), `duration` (seconds)
- Captures all messages on the specified channel for the given time
- Returns a DataFrame with timestamp, channel, ID, and data

### 2. Data Analysis & Querying
Analyze captured CAN data using SQL-like queries.

**Usage**:
```
read("capture.log")
sql("SELECT * FROM df WHERE id = '123'")
```

### 3. Message Replay
Replay captured or crafted CAN messages.

**Usage**:
```
play("can0", dataframe)
playmsg("can0", "123#DEADBEEF")
```

### 4. Intelligent Fuzzing
Generate fuzzed CAN messages for security testing.

**Usage**:
```
fuzz(dataframe, 100)
```
- Creates 100 variations of messages with random data modifications
- Useful for identifying vulnerable ECUs and testing error handling

### 5. Smart Scan
Automatically identify signal vs noise in CAN traffic.

**Usage**:
- Select "Smart Scan" from the main menu
- Follow on-screen instructions to capture baseline and signal data
- Tool automatically differentiates between noise and intentional signals

### 6. Remote Access via Telegram
Control CANalyse remotely through Telegram bot.

**Setup**:
1. Create a Telegram bot via @BotFather
2. Set the bot token in CANalyse settings
3. Use Telegram commands to control the tool remotely

**Available Commands**:
- `scan("can0", "10")` - Scan for 10 seconds
- `read("file.log")` - Load log file
- `fuzz(df, 50)` - Generate 50 fuzzed messages
- `play("can0", df)` - Replay messages

### Session Management

```
save(dataframe, "output.csv")   # Save to CSV format
save(dataframe, "output.log")   # Save to CAN log format
save(dataframe, "output.asc")   # Save to Vector ASC format
save(dataframe, "output.blf")   # Save to Binary Log Format

save(dataframe, "output.mf4")   # Save to ASAM MF4 format
save(dataframe, "output.db")    # Save to SQLite database

read("input.asc")               # Read from ASC file
read("input.blf")               # Read from BLF file
read("input.trc")               # Read from TRC file
read("input.mf4")               # Read from MF4 file
read("input.db")                # Read from SQLite database
```

## CAN Bus Fundamentals

### How CAN Works
- **Messages**: Each CAN message contains an ID (identifier) and data payload
- **ECUs**: Electronic Control Units respond to specific message IDs
- **Broadcast**: All ECUs receive all messages but only respond to relevant IDs

### Attack Methodology
1. **Reconnaissance**: Scan network to identify active ECUs and message patterns
2. **Analysis**: Compare normal vs triggered states to identify control messages
3. **Testing**: Use fuzzing to test ECU robustness and identify vulnerabilities
4. **Exploitation**: Replay identified control messages

### Common Attack Vectors
- **Message Injection**: Sending crafted messages to control vehicle functions
- **DoS Attacks**: Flooding the bus with high-priority messages
- **Parameter Manipulation**: Modifying data fields in legitimate messages
- **Fuzzing**: Testing ECUs with unexpected or malformed data

## Troubleshooting

### Common Issues

**"Invalid channel" Error**
- Verify your CAN interface is properly configured
- Check interface permissions (may need sudo on Linux)
- Ensure the interface exists (`ip link show` on Linux)

**Telegram Connection Issues**
- Verify bot token is correct
- Check internet connectivity
- Ensure bot has proper permissions

**Import Errors**
- Install missing dependencies: `pip install -r requirements.txt`
- Verify Python version (3.8+ required)
- Check for conflicting package versions

### Performance Tips
- Use appropriate scan durations (start with short scans)
- Filter data early to reduce memory usage
- Save large datasets to disk rather than keeping in memory

## Technical Details

### Supported CAN Interfaces
- SocketCAN (Linux)
- PCAN (Windows/Linux)
- CANalyst-II
- USBtin
- IXXAT
- Virtual CAN (for testing)

### Data Formats
- **CSV**: Standard spreadsheet format
- **LOG**: Native CAN log format compatible with other tools
- **ASC**: Vector CAN log format (industry standard)
- **BLF**: Binary Log Format (Vector tools)
- **TRC**: Peak CAN trace format
- **MF4**: Measurement Data Format (ASAM standard)
- **SQLite**: Database format for large datasets
- **DataFrames**: In-memory pandas DataFrames for analysis

